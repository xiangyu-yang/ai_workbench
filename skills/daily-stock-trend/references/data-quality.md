# 盘前与盘中数据质量

## 先判断数据阶段

| 状态 | 含义 | 报告写法 |
| --- | --- | --- |
| 盘前 | 最新日线早于今天，报价可能是昨收/竞价 | “盘前参考，开盘后需刷新” |
| 盘中 | 今日 K 线成交量明显低于 20 日均量一半 | “盘中未完成，量比待收盘确认” |
| 收盘后 | 今日日线已完整或接近完整 | “收盘数据” |
| 延迟/停牌 | 最新日线超过 7 天或接口无更新 | “可能停牌/延迟，不足以判断” |

脚本返回 `phase`、`partialBar`、`quoteTime`、`lastDate`；不要自己改写成“实时”。

## 必查项

- 代码与名称是否一致；中文名称解析失败时不要猜代码。
- 最新日线日期、报价时间、币种、市场。
- 当前价/昨收/缺口是否来自同一市场、同一币种。
- 成交量单位：A 股“手”、港股/美股“股”，不跨市场比较绝对量。
- 复权方式：前复权价格不能和未复权历史价位混用。
- 停牌、涨跌停、盘前薄报价、财报跳空。
- 港股/美股没有结构化财务时，不得补写营收、净利、ROE、现金流。

## 数据冲突

- 同一指标两个来源差异 >5%：并列说明，不要静默选一个。
- 报价与日线收盘不一致：说明是盘前/盘中/延迟，不当成“数据错误”或“必然跳空”。
- 财报报告期累计 vs 单季：不能直接年化或和单季比较。

## 失败处理

1. 行情脚本最多重试一次（检查代码、网络、市场）。
2. 仍失败：明确写“未获取”，给条件式观察清单；不生成带假数字的模板。
3. 用户提供 CSV：使用 `technical_scan.py`，标注“用户提供，可能非最新”。
4. 不通过抓取网页补当日价格或财务数据。

## 报告头模板

```text
数据时间：YYYY-MM-DD HH:MM（时区）
最新日线：YYYY-MM-DD
市场/币种：A股/港股/美股，CNY/HKD/USD
阶段：盘前 / 盘中 / 收盘后 / 延迟
来源：脚本返回的 source
```
