# 股票深度分析与预测

## 语言

默认使用简体中文输出，标题、表格、图表说明、工具解释与免责声明都必须中文；即使用户上传的素材或工具返回值是英文，也先翻译再用中文分析，不要切换成英文。

## 标的锁定（每轮必须重新解析）

- 每一轮只分析**用户最新消息中的标的**，不得复用上一轮、历史对话或技能示例里的股票代码。
- 用户只给中文名称时，**直接把名称传给脚本**（例如 --symbol 贵州茅台），脚本会通过东方财富搜索解析为正确代码，不要自己猜代码。
- 如果名称和代码冲突，以用户明确写出的代码为准，并在报告开头说明；不确定时先向用户确认。
- 报告开头必须同时写“名称 + 解析后代码”，并核对两者一致。

## 何时使用

当用户要求分析某只股票、判断未来走势、评估估值、制定买入/卖出区间、比较同业、做持仓风险检查时使用。典型触发：
- “深度分析一下贵州茅台 / 中国移动 / 某只美股”
- “预测一下未来 3-12 个月走势，给目标价和情景”
- “现在贵不贵？DCF 和可比公司怎么看”
- “帮我判断这份持仓的风险和止损位”

如果用户只是问股价、涨跌幅或一条新闻，不要触发完整技能，直接回答并给来源。

## 先确认

在开始研究前，先确认或声明默认值：
1. 标的与市场：A 股 / 港股 / 美股，代码、币种、财年。
2. 决策问题：买入、持有、卖出、观望、仓位调整。
3. 时间维度：短线（1-4 周）、波段（1-3 月）、中期（6-12 月）、长期（3 年+）。
4. 投资者类型：价值、成长、股息、交易；风险承受度。
5. 数据截止日：股价、财报、指引、行业数据的日期。
6. 是否需要技术面/交易执行建议；若不需要，基本面与估值优先。

## 工作流

### 1. 建立研究框架

按 references/research-framework.md 的五层框架：
生意模式 → 行业结构 → 护城河 → 管理层与治理 → 财务质量。
若公司有应收/存货/现金流异常、关联交易或审计风险，追加读取 references/forensic-accounting.md。
不要一上来堆指标；先回答“这家公司靠什么赚钱、能否持续”。

### 2. 获取真实行情与量价诊断

必须优先获取真实日线，不允许凭记忆写“今日行情”：
- 支持 A 股代码/中文名称、港股代码、美股代码；中文名称由脚本自动解析。
- 调用 run_skill_script 时必须同时传：
  - skill：股票深度分析与预测
  - script：scripts/live_market_scan.py
  - args：["--symbol","<当前标的代码或名称>","--days","250","--format","markdown"]（数组，不要传 JSON 字符串；把占位符替换成当前标的）
- 如果脚本失败，最多重试一次（检查代码、网络或改用 fetch_market_data.py）；不要连续用 read_url 猜接口 URL。仍失败就让用户上传 CSV。
- 脚本会拉取腾讯公开行情，输出：收盘/涨跌幅/成交额、换手率、5 日与 20 日量比（当日成交量/前 N 日均量）、量价组合（放量上涨/放量下跌/缩量上涨/缩量下跌）、5 日量价背离、OBV/MFI/VWAP、均线、RSI、ATR、支撑阻力。
- 如果实时接口失败，先调用 scripts/fetch_market_data.py 检查代码与网络；仍失败则让用户上传 CSV 或稍后重试。**禁止编造当日行情。**
- live_market_scan 成功后，直接进入研究报告；不要再用 read_url 抓新浪/同花顺/雪球等页面补数据。
- 报告第一屏必须有“行情快照 + 量价诊断”，并注明数据截止时间与来源；脚本同时返回 8 期基本面与 PE 锚定情景，标准请求不需要再调用其他脚本。
- 如果用户只提供 CSV，则用 scripts/technical_scan.py 分析，并注明数据由用户提供、可能非最新。

### 2.5 多标的推荐 / 选股

当用户要求“推荐几只/选股/潜力股/龙头股”时：
- 不要用单股脚本反复读取同一份框架；先明确或假设范围（行业、风格、市值、风险），并在报告开头写明。
- 调用 scripts/screen_stocks.py 获取候选池，例如：
  - args：["--limit","10","--min-market-cap","300","--max-pe","40","--format","markdown"]
  - 行业筛选可用 --industry；潜力股可加大 --max-pe、降低市值门槛。
- 脚本输出代码、名称、行业、价格、涨跌幅、PE/PB、总市值、换手率；它只是候选池，不是买入建议。
- 从候选池中选择最多 3 只，再调用 live_market_scan.py 做量价与基本面核验；不要对每只股票重复读取同一 reference。
- 推荐结论必须写明筛选条件、数据截止、主要风险和“不构成投资建议”。

### 2.6 大盘、指数与跨市场

当用户问“大盘/市场/风格/跨市场”，先调用 scripts/market_overview.py：
- 全市场：args ["--market","all","--days","120","--format","markdown"]
- A 股：--market cn；港股：--market hk；美股：--market us
- 输出主要指数、当日/20 日涨跌、MA20/60、量比与趋势。
- 大盘分析必须结合估值、盈利周期、流动性与政策；单日涨跌不能直接外推。
- 个股与大盘要分层：先大盘环境，再行业，再个股 α。
- 若加载了“深度调研方法论”，优先读取其 references/evidence-standards.md，用多源取证、反方观点和来源审计；在 UI 中会标记该技能已使用。

### 3. 取证与数据审计

- **A 股基本面已包含在 live_market_scan 中**：最新报告期营收、归母净利、同比、ROE、毛利率、净利率、负债率、EPS/BPS、经营现金流，以及近 8 期趋势与 PE 锚定情景。
  - 只有用户明确要求更长历史、更多科目或自定义 DCF 时，才调用 scripts/fetch_fundamentals.py；标准分析不要再调用脚本。
  - 脚本返回结构化字段，禁止自己解析交易所/财经网站 HTML 或原始数组。
- **不要用 read_url 抓新浪/同花顺/雪球 F10 等原始 HTML**；接口常乱码或返回巨型数组。脚本失败时明确写“基本面未获取”，不要写数据处理教程、不要解析原始数组。
- 数据获取最多：行情脚本 1 次、基本面脚本 1 次、必要的公开检索 1 次；失败后立即收敛，不要连续换 URL。
- 港股/美股：live_market_scan 只提供行情、量价、PE/PB/市值，没有营收、净利、ROE、毛利率、现金流等结构化财务数据。
  - **这些财务字段一律写“未获取”，禁止用“约/估算/~”填数字，禁止编造财务表。**
  - 不要用 read_url / http_request 抓财经网页；可以用生意模式、竞争格局、PE/PB 与情景假设做定性分析，并明确数据缺口。
- 允许使用 web_search 检索**新闻、公告、行业事件和催化剂**，但必须标注来源与日期；禁止用搜索结果补写营收、净利、ROE、毛利率、现金流等财务数字。
- 禁止通过 read_url / http_request 抓取财经网页补财务数字；行情脚本失败时最多重试一次，然后明确说明缺口。
- 一手来源优先：年报/季报、招股书、交易所公告、业绩会、官方指引、监管文件。
- 二手来源：权威行业报告、同业财报、可信媒体；标注日期与原文位置。
- 每个关键数字必须有来源、口径、币种、时间。
- 至少一个反方来源；不把管理层指引当已实现事实。
- 数据不足时写“未获取”，不要用记忆或估算冒充事实。

### 4. 基本面与财务质量

- 增长：收入/利润/用户/单价拆分，区分量、价、结构。
- 盈利：毛利率、经营利润率、净利率、ROIC/ROE，和同业、历史比。
- 现金流：经营现金流、资本开支、自由现金流、现金转换率。
- 资产负债：净现金/净负债、利息覆盖、到期结构、或有负债。
- 稀释：股本变化、股权激励、可转债。
- 会计质量：应收/存货/合同负债异常、非经常性损益、关联交易。
- 有财务异常或治理疑点时，读取 references/forensic-accounting.md，按红旗分级写证据与待验证项。

### 5. 估值：多方法交叉

读取 references/valuation-playbook.md，至少使用两种方法：
- **DCF**：明确 FCF 口径、增长、WACC、永续增长、净债务、股本。
- **反向 DCF**：当前股价隐含了什么增长？这个增长是否可信？
- **相对估值**：PE/PB/EV-EBITDA/PS，和同业、历史分位比；注意周期与会计差异。
- **分部估值（SOTP）**：多业务公司分别估值后加总。
- **股息/回购**：股息率、派息率、回购收益率。
- 先读取 references/sector-playbook.md，选择与行业匹配的 KPI 和估值方法；银行/保险/地产不得机械套 DCF。

**标准请求不要调用 equity_valuation.py**：live_market_scan 已给出 PE 锚定情景。只有用户提供真实 FCF/WACC/净债务等假设，或明确要求自定义 DCF 时才使用 scripts/equity_valuation.py；脚本输出的数字仍需检查假设。

**禁止使用合成示例数据做真实标的估值**：如果技能中没有真实输入，就不要调用演示脚本；真实标的只使用实时脚本、结构化基本面接口和用户提供的假设。

### 6. 技术面与交易时机（可选）

如果用户需要入场/止损/仓位，读取 references/technical-playbook.md，并结合 live_market_scan.py 的输出（或用户 CSV 的 technical_scan.py 结果）。
技术面只用于**执行时机和风险管理**，不能替代基本面 thesis。至少看：
- 趋势：价格与 SMA20/60/200、均线排列；
- 动量：RSI、MACD，避免超买追高；
- 波动：ATR、布林带、年化波动；
- 量价：放量突破/缩量回调；
- 关键位：近期高低点、成交密集区、前高/前低。

### 7. 催化剂与风险

- 催化剂：财报、指引、产品发布、价格调整、政策、并购、回购、指数纳入。
- 风险：需求、竞争、价格战、监管、汇率、利率、地缘、流动性、治理、会计。
- 为每个催化剂/风险标注时间窗、概率、影响方向与可验证信号。
- 读取 references/catalyst-playbook.md，把财报、产品、价格、政策、资金事件分开。

### 8. 概率化预测

不要给单点“必涨/必跌”结论。按以下结构：
- 悲观 / 基准 / 乐观三种情景；
- 每种情景给概率、目标价/区间、触发条件、关键假设；
- 计算概率加权目标价、期望收益、下行风险；
- 给出置信度（高/中/低）和**失效条件**（什么发生则 thesis 不成立）；
- 明确时间维度；3 个月和 12 个月结论可以不同。
- 使用回测/历史胜率时读取 references/data-quality-and-backtesting.md；没有真实回测输入，不得写“历史胜率/年化收益”。

预测是条件概率，不是承诺。必须写“不构成投资建议”。

### 9. 生成报告

按 assets/equity-research-template.md 输出：
摘要（结论/评级/目标区间/置信度）→ 生意与行业 → 护城河 → 财务 → 估值 → 情景预测 → 催化剂 → 风险 → 反方观点 → 数据与来源。
最终回复必须包含可读的报告正文（至少结论卡片），或者实际调用 workspace_write；**禁止只输出“现在开始撰写/接下来生成报告”等过渡语后结束**。
用 workspace_write 写入 Markdown，文件名含标的与日期。**workspace_write 成功后，聊天回复给 15-20 条核心结论、关键数据和交付物文件名，完整正文放在交付物中**。**深度报告正文控制在 5000-6500 汉字，总文件不超过 18KB**；不要把 skill references、原始 JSON 或整段工具输出复制进报告，避免超长工具参数导致模型解析失败。

普通分析**不要调用 create_task**；只有用户明确要求后台执行、持续跟踪或定时任务时才创建任务。

### 10. 质量门槛

- 报告开头有真实行情快照、数据截止日与来源；不得用记忆替代当日行情。
- 量价必须说明：5/20 日量比（当日成交量/前 N 日均量）、量价组合、5 日背离、关键位；不能只写“放量”或“缩量”，也不要把量比解释成“N 日均量/60 日均量”。量比阈值以脚本为准：≥1.2 放量、≤0.8 缩量，不要简单写成“>1 就是放量”。
- 每个关键数字有来源、日期、口径；财务表格只能使用工具返回字段，缺失写“未获取”，禁止补写记忆中的历史财务数字。
- 真实标的只使用实时脚本与结构化基本面接口；不要引用演示数字。
- 行业规模、批价、分红率、历史 PE 分位、同业收入等没有通过工具获取的数字，只能写“需核验/未获取”或定性描述，不得编造精确值。
- DCF 的 FCF 基数若未从结构化财报计算，必须标为情景假设，不能写成已实现事实。
- 至少两种估值方法，且说明差异。
- 至少一个反方观点和失效条件；有财务异常时，至少一条 forensic-accounting 红旗。
- 情景概率合计 100%，目标价与假设一致。
- 区分事实、推断、预测。
- 不承诺收益，不使用“稳赚/必涨/内部消息”。
- 不提供内幕信息、操纵市场或规避监管的建议。

## 深度报告最低结构

除用户明确要求“简要分析”外，深度报告必须包含以下结构，不能只给摘要：

1. **数据质量与口径**：行情/财报截止日、盘中或收盘、复权、币种、单位、缺失字段。
2. **结论卡片**：评级、时间维度、目标区间、概率加权收益、置信度、失效条件。
3. **行情快照 + 量价诊断**：行情表、5/20 日量比、量价组合、5 日背离、OBV/MFI/VWAP、关键位。
4. **生意模式与行业格局**：收入结构、客户、成本、竞争、供需、政策、行业 KPI。
5. **护城河与管理层**：逐项证据与反证，资本配置、治理风险。
6. **财务质量**：近 8 期趋势表、营收/利润/ROE/毛利率/现金流/负债率，财务红旗。
7. **估值**：PE 锚定情景、反向 DCF、相对估值、WACC/增长敏感性；至少两种方法。
8. **情景预测**：下季度与 12 个月，悲观/基准/乐观，概率合计 100%，触发条件与失效条件。
9. **催化剂与风险**：表格化，含时间窗、概率、影响方向、验证信号。
10. **技术面与执行**：趋势、动量、波动、支撑阻力、入场/止损，标注“仅执行参考”。
11. **反方观点与数据缺口**：最强反方论点、可能错在哪里、缺失数据。
12. **监控仪表盘**：关键指标、阈值、频率、数据来源。
13. **来源与免责声明**：数据来源、截止日期、免责声明。

## 输出规范

- 开头先给“行情快照 + 量价诊断”，再给结论卡片；写明数据截止日、来源、5/20 日量比与量价组合。
- 深度分析可读取 1-4 个**不同**的 references；首选 assets/equity-research-template.md；若加载了深度调研方法论，优先读取其 references/evidence-standards.md；再按需选择研究框架、估值或量价 playbook。同一路径只读一次，禁止遍历或重复读取。
- 工具结果和旧对话可能被上下文压缩；需要完整数字/表格时调用 evidence_search/evidence_read，需要上一轮报告/结论时调用 history_search，不要要求用户重发。
- 当前轮 live_market_scan / 参考文件已经返回时，优先直接使用；不要为了“再确认”反复调用记忆工具。evidence_search 返回 0 条或 evidence_read 失败后禁止连续重试，直接基于已有数据完成报告。
- 结论卡片：评级（买入/增持/中性/减持/回避）、时间维度、目标区间、概率加权收益、置信度。
- 目标价用区间，不用单点；说明对应情景与概率。
- 估值表展示关键假设与敏感性（WACC ±1%、增长 ±2%）。
- 技术面单独成节，明确“仅用于执行”。
- 来源表含标题、机构、日期、链接/文档。
- 结尾固定免责声明。

## 脚本约定

脚本从 SKILL_INPUT 或 --input 读取 JSON/CSV，输出 JSON 或 Markdown。实时分析优先使用 live_market_scan.py；它内部调用 fetch_market_data.py。脚本只做计算与格式化；假设是否合理由你判断。不要把脚本输出直接当投资结论。
