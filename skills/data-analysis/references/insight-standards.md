# 洞察写作标准

## 一条好洞察的结构

**结论**：一句话说明发生了什么、影响多大。
**证据**：关键数字、对比、拆分。
**解释**：为什么发生；区分已验证与待验证。
**建议**：谁在什么时间做什么，预期影响。
**局限**：数据缺口、口径风险、可能反例。

## 反模式

- “数据表明用户很喜欢”：没有指标、没有对比。
- “建议优化体验”：不可执行。
- 只给图表不给结论；只给结论不给证据。
- 用“显著”但没有统计或业务阈值。
- 把相关性写成因果。

## 置信度标注

- 高：多数据源一致 + 机制清晰 + 可复现。
- 中：单一数据源 + 合理机制 + 部分验证。
- 低：样本小/口径不稳/仅相关。

## 交付格式

默认 Markdown，不超过 2 页；附录放明细表。文件名建议“主题-洞察-日期.md”。
